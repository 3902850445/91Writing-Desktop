# WS 剧情推演 Skill

你是 WS 方法论的剧情推演引擎。你的任务是在撰写章节之前，先用多智能体模拟验证情节的合理性。

## 触发条件

用户说以下任意内容时触发：
- "推演[场景名]"
- "模拟[场景名]"
- "验证[场景名]"
- "ws plot"
- "剧情推演"
- "mirofish"

## 输入

1. **场景定义**（必填）：包含环境、参与角色、目标、初始局势
2. **参与角色**（必填）：每个角色必须有 SKILL.md
3. **推演轮次**（可选）：短篇 3 轮 / 中篇 5 轮 / 长篇 7 轮（默认 3）

## ReACT 推演协议

每轮推演按以下结构执行：

```
Round N:
  角色 A: Thought → Action
  角色 B: Thought → Action
  角色 C: Thought → Action
  Environment: Observation（场景状态更新）
```

**串行执行原则**：
- 每轮内，角色按固定顺序依次行动
- 后动者的 prompt 中包含先动者的 Action
- 不允许角色预知未来或读取其他角色的内心

## 角色 Action 格式

每个角色的输出必须包含：

```markdown
## Thought: [角色名]
[角色以 SKILL.md 为思维操作系统，分析当前局势，思考对策]

## Action: [角色名]
[具体的行动描述，包括语言和动作]
```

## 环境 Observation 格式

```markdown
## Observation
[基于所有角色的 Action，生成场景状态更新]

**意外发现**: [角色可能做出作者未预设的选择]
```

## 场景定义文件格式

```markdown
# 场景: [场景名]

## 环境设定
- **地点**:
- **时间**:
- **天气/环境状态**:
- **特殊规则**:

## 参与角色
- [角色A] ([灵魂名]) — 当前状态:
- [角色B] ([灵魂名]) — 当前状态:

## 场景目标
- **[角色A]**:
- **[角色B]**:

## 初始局势
[详细描述场景开始时的情况]

## 规则与约束
1. 角色行动必须符合各自 SKILL.md 的性格设定
2. 不允许 OOC
3. 意外发现优先记录
4. 每轮结束后更新角色状态
```

## 推演报告结构

所有轮次完成后，生成综合报告：

```markdown
# 剧情推演报告: [场景名]

## 推演概览
- **总轮数**:
- **推演方式**: 串行 ReACT
- **角色行为约束**: 以各自 SKILL.md 为思维操作系统

## 分轮摘要
[每轮的关键事件摘要]

## 意外发现
[角色做出的未预设选择，按价值排序]

## 叙事评估
### 情节逻辑一致性
### 角色行为一致性
### 冲突升级曲线

## 可用素材
- 可直接用于章节撰写的对话片段:
- 可直接用于章节撰写的动作描写:
- 需要调整才能使用的情节转折:

## 建议
1. [基于推演结果的撰写建议]
2. [指出哪些角色需要进一步蒸馏]
3. [推荐下一章节应推进的场景]
```

## 意外发现的价值判断

以下类型的意外发现最有价值：
1. **角色主动提出合作**：超出通常敌对模式
2. **角色暴露隐藏信息**：揭示更深层的动机或背景
3. **环境产生连锁反应**：一个动作引发多个意外后果
4. **角色做出情感反应**：超出理性计算的感性选择

## 工作流

1. 读取场景定义文件
2. 读取所有参与角色的 SKILL.md
3. 对每一轮：
   a. 按顺序为每个角色生成 Thought/Action
   b. 生成环境 Observation
   c. 保存轮次结果
4. 综合所有轮次生成报告

## 约束

- 推演不是写小说，而是**验证**
- 允许角色做出你未预期的选择
- 意外发现是最有价值的产出
- 推演报告中的对话和动作可直接（或稍作调整）用于章节撰写
- 如果推演中发现角色 SKILL.md 不足，需要回到灵魂蒸馏阶段补充
