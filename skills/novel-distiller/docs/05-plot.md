# 剧情推演（Plot Simulation / MiroFish）

## 概念

剧情推演是 WS 方法论的核心创新：在撰写章节**之前**，先用多智能体模拟验证情节的合理性。每个角色以各自的 SKILL.md 为思维操作系统，在场景中按 ReACT（Reasoning + Acting）模式行动。

目的：**先验证，再撰写**——避免写到一半发现情节崩坏、角色 OOC、逻辑不通。

## ReACT 推演协议

每轮推演按以下结构执行：

```
Round N:
  角色 A: Thought → Action
  角色 B: Thought → Action  
  角色 C: Thought → Action
  Environment: Observation（场景状态更新）
```

**串行执行原则**：
- 每轮内，角色按固定顺序依次行动
- 后动者的 prompt 中包含先动者的 Action
- 不允许角色预知未来或读取其他角色的内心

## 两阶段工作流

### 阶段 1：生成推演准备文件

```bash
ws plot 场景名 --rounds 3
```

需要前置条件：
- `scenes/场景名.md` — 场景定义文件（环境、参与角色、目标、初始局势）
- `souls/角色名/SKILL.md` — 所有参与角色的 SKILL.md

生成的文件：
- `scenes/场景名/manifest.md` — 推演清单
- `scenes/场景名/simulation_guide.md` — 推演协议指南
- `scenes/场景名/rounds/round_NN_prompt.md` — 每轮 prompt

### 阶段 2：串行执行 ReACT

对每一轮，按以下方式执行：

1. **角色 Thought/Action**：对每个角色，启动一个 Agent
   - System: "你是 [角色名]，以你的 SKILL.md 为思维操作系统"
   - User: "当前场景状态 + 已发生的行动，输出你的 Thought → Action"

2. **环境 Observation**：收集所有角色的 Action 后，启动环境 Agent
   - User: "基于以下角色行动，生成 Observation 和场景状态更新"

3. 将完整轮次保存到 `scenes/场景名/rounds/round_NN.md`

### 阶段 3：生成报告

```bash
ws plot 场景名 --report
```

综合所有轮次，生成 `scenes/场景名/report.md`，包含：
- 推演概览（总轮数、方式、约束）
- 分轮摘要
- 意外发现（角色可能做出作者未预设的选择）
- 叙事评估（情节逻辑、角色一致性、冲突升级）
- 可用素材（可直接用于章节的对话/动作描写）

## 场景定义文件格式

```markdown
# 场景: 场景名

## 环境设定
- **地点**: 
- **时间**: 
- **天气/环境状态**: 
- **特殊规则**: 

## 参与角色
- 角色A (灵魂名) — 当前状态: 
- 角色B (灵魂名) — 当前状态: 

## 场景目标
- **角色A**: 
- **角色B**: 

## 初始局势
...

## 规则与约束
1. 角色行动必须符合各自 SKILL.md 的性格设定
2. 不允许 OOC
3. 意外发现优先记录
4. 每轮结束后更新角色状态
```

## 轮次推荐

| 篇幅 | 推荐轮次 | 说明 |
|------|---------|------|
| 短篇 | 3 轮 | 快速验证核心冲突 |
| 中篇 | 5 轮 | 充分展开角色互动 |
| 长篇 | 7 轮 | 深度挖掘意外发现 |

## 注意事项

- 推演不是写小说，而是**验证**——允许角色做出你未预期的选择
- 意外发现是最有价值的产出，它们往往成为章节中最精彩的情节转折
- 推演报告中的对话和动作可以直接（或稍作调整）用于章节撰写
- 如果推演中发现角色 SKILL.md 不足（角色行为不统一），需要回到灵魂蒸馏阶段补充
